# 설계: 정책·피그마 대조

## 목표

정책 문서(Confluence)·디자인(피그마)·앱 화면 셋이 서로 어긋나는 곳을 찾는다. 사람이 문서와 화면을 일일이 잇지 않는다. 문서·디자인은 **읽기만** 한다.

## 출처

| 출처 | 읽는 방법 |
| --- | --- |
| 정책 | `policy.confluence`의 스페이스에서 제목에 `titleQuery`가 든 페이지 + `policy/sources.json`에 등록한 페이지. 범위 지정 읽기 토큰을 `api.atlassian.com/ex/confluence/<cloudId>` 게이트웨이로 부른다 |
| 피그마 | 정책 본문의 피그마 링크 + 프론트 코드(`figma.frontRepo`, Next.js App Router)에서 찾은 화면별 노드. 스토리북 `parameters.figma` 링크와 `Figma 12:34` 주석을 `git grep`으로 모은다. 노드 문구는 Figma REST(`X-Figma-Token`)로 읽는다 |
| 앱 | 실기기에서 그 화면을 열어 글자·스크린샷 |

## 흐름

1. **바뀜 감지**(매일 02시, LLM 없음): 페이지마다 본문 해시를 지난 스냅샷과 비교해 추가·변경·삭제를 기록한다.
2. **규칙 뽑기**(Claude CLI): 바뀐 페이지만 다시 뽑는다. 종류는 copy(안내 문구), value(금액·횟수 같은 값), behavior(상태에 따라 보이고 숨는 것). 근거 인용이 본문에 그대로 없으면 버린다. 규칙마다 어느 화면 경로에서 보이는지 고른다(시나리오 + 화면 지도 경로 중에서).
3. **피그마 문구 읽기**.
4. **화면 대조**(점검 때 데이터 QA 뒤): 화면을 열고
   - copy·value 규칙은 화면 글자에 있는지 글자로 본다.
   - 피그마 문구 중 「화면에 있는데 피그마에 없음」만 본다(노드가 다른 단계·오류 상태까지 담아 반대 방향은 잡음이 많다).
   - behavior 규칙은 Claude가 화면 글자와 스크린샷으로 판정한다. 개인정보 경로는 스크린샷을 보내지 않는다. 판정은 화면·규칙·피그마 해시로 캐시한다.

## 어긋남 분류

| 분류 | 뜻 |
| --- | --- |
| 버그 후보 | 정책·피그마는 같은데 앱만 다르다. **이것만 실패** |
| 앱 반영 전 | 정책이 최근(14일 안)에 바뀌었다 |
| 정책 문서가 뒤처짐 | 피그마·앱은 같은데 정책만 다르다 |
| 문서 갱신 누락 또는 버그 | 앱이 바뀌었는데 문서가 그대로다 |
| 문서끼리 어긋남 | 정책·피그마가 서로 다르다 |

「열면 보이지 않는」(특정 상태가 필요한) 규칙은 판정하지 않고 상황 필요로 센다.

## 무시

결과 줄마다 무시할 수 있다. 무시는 그때의 정책·노드 해시에 묶여, 문서나 디자인이 바뀌면 풀린다. 무시 목록은 저장소에 커밋한다.
